# memoryboost 三层架构详解

## 设计目标

- **统一记忆**：所有项目共享一份全局记忆，不再各记各的
- **可迁移**：换工具、换模型、换机器，拷一个文件夹就走
- **零依赖**：不引入数据库/MCP/npm 包，git 即备份

## 三层结构

### 第一层：总库（唯一事实源）

```
<记忆库>/
├── AGENTS.md              # 全局入口：身份/偏好/铁律/使用规则/目录索引
├── projects/
│   └── <项目>.md          # 项目权威档案（每项目一页）
├── topics/
│   ├── decisions.md       # 跨项目关键决策日志
│   └── patterns.md        # 可复用打法
└── templates/             # 建档/交接/spec 模板
```

**加载方式**：全局 `CLAUDE.md` 用一行 `@<路径>/AGENTS.md` import（会话开始时原文展开，所以入口文件必须瘦身，建议 ≤150 行）；深层档案按需读取（入口里写明"需要项目背景时读 projects/<项目>.md"）。

### 第二层：项目根（同步副本）

每个项目根目录：

- `AGENTS.md`：项目档案的同步副本（脚本生成，勿手改）——Cursor / Codex / Gemini CLI **原生读取**这个文件
- `CLAUDE.md`：一行 `@AGENTS.md` 桥接（Claude Code 不原生读 AGENTS.md，经 import 接入）

### 第三层：自动记忆（草稿层）

各工具自带的自动记忆（如 Claude Code 按项目目录隔离的 auto-memory）继续自然积累，定位为**草稿层**。会话中发现持久事实时，主动并入总库对应档案；冲突时以总库为准。

## 同步脚本设计

`scripts/sync-project-agents.ps1` 做两件事：

1. 把 `projects/<项目>.md` 复制到映射中的项目根 `AGENTS.md`
2. 项目根 `CLAUDE.md` 不存在时生成一行 `@AGENTS.md`（已存在则跳过，绝不覆盖）

映射在 `sync-map.json` 中维护：

```json
{ "demo-shop.md": "demo-project" }
```

键 = 档案文件名，值 = 项目根目录（相对映射文件所在目录或绝对路径）。

## 设计取舍

### 为什么不用数据库/向量检索？
- 记忆的瓶颈不是检索，是**沉淀与维护**——文件 + git 让沉淀有版本、可审计、可回滚
- 零部署、零迁移成本：拷文件夹即全部资产
- 单人或小团队的记忆量级（几十个档案文件）不需要检索增强；需要时再引入，文件结构天然兼容

### 为什么入口文件要瘦身？
import 在会话开始时原文展开，会占上下文。深层内容走"按需读取"，让模型用 Read 工具现取现用——总量不限，常驻精干。

### 为什么档案权威版在总库、项目根只放副本？
单一事实源避免两处漂移；项目根副本服务于"其他工具原生读取"这个硬需求，由脚本单向同步保证一致。
